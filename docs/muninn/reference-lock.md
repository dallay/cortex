identities, versions, case results, a post-operation graph, and namespace
cleanup. The committed file replaces the random owner with a constant prefix
to avoid versioning transient identifiers.

- Real CRUD for sessions and messages: observed.
- `metadata` flattening in Neo4j and removal of null values: observed.
- Invalid role and null content validation: observed.
- Owner isolation for retrieval and deletion: observed.
- `get_message` without the correct owner: observed as empty.
- `delete_message(owner_id=...)`: returns `false` for both owners and leaves the

  remains **an open oracle discrepancy**, not a Muninn implementation claim.
- Delete-all by owner clears messages and conversations. Global indexes and
  constraints remain installed; they are not namespace data.

## Generated inventory

`specs/parity-matrix.csv` is generated by `dev/muninn/reference.py inventory`
from the two pinned checkouts. The recipe verifies HEAD and tracked files before
regeneration. The matrix preserves original clause/requirement text and links
rows to the pinned SHA. It does not turn declarations into a runtime pass.

Categories: sections/clauses, normative paragraphs, TCK cases and fixtures,
Python signatures, models and protocols, MCP tools/registration, backend
exceptions, Cypher DDL/indexes, and embedding/LLM declarations. All Muninn states
remain `no_implementado`. The inventory is a review baseline; it does not prove
functional completeness.

## Gates still open

1. No Muninn service parity or Bronze→Platinum acceptance exists.
2. The deletion discrepancy needs separate characterization; the oracle must
   not be changed to force the expected result.
3. Retrieval, real embeddings, LLMs, external integrations, and advanced paths
   were not executed. The G0 API unit pins their references, but does not run them.
4. Native `Exception("Not implemented")` and `NotSupportedError` differences
   are recorded in the matrix; Muninn must not reduce them to one generic error.
5. There is no syntax-independent Cypher contract or backend capability matrix yet.
6. Model provenance is pinned in
   [the artifact lock](../../dev/muninn/fixtures/artifact-lock.json), but numeric cross-validation
   and local inference remain unexecuted. A checksum does not prove parity.
7. Neo4j 5.26 bundles APOC in `labs/`, but it was not activated. Its receipt
   does not constitute functional plugin support.

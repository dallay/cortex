# Requirements

### Overview
Add a **scoring stage** that captures one immutable signal snapshot per selection invocation over eligible candidates, computes pure per-candidate `ScoreComponents` with raw evidence and optional normalized values, and produces a `SelectionReason` explaining the actual selection decision. Also harden `WeightedRandom` validation with explicit typed errors instead of silent first-candidate fallback.

### Goals
- Deliver evidence + normalization + explanation foundation for routing
- Preserve existing Priority/RoundRobin/WeightedRandom selection behavior
- Keep scoring side-effect-free and testable
- Fix silent weighted-input mismatches

### Scope

**In Scope:**
- New `scoring.rs` module in `rook-usecases` with pure normalization logic
- Signal snapshot types: `SignalsSnapshot`, `CandidateSignals`, `ScoreComponents`, `SelectionReason`, `UnknownReason`
- Inverse min-max normalization for latency (p50/p95 separately) and cost dimensions independently
- Integration between eligibility and selection in both completion and streaming paths
- `WeightedRandom` validation: explicit errors for length mismatch, invalid weights, non-selectable zero set
- `SelectionReason` built from the actual selected provider and evidence
- Regression tests for legacy behavior, normalization boundaries, and weighted errors

**Out of Scope:**
- New policy engine or six-policy configuration (DALLAY-774)
- Selection reason telemetry emission (DALLAY-779)
- Machine-learned ranking, synthetic scores, scoring-weight tuning
- Combo weighted configuration
- Persistence/migration changes or UI work
- Changing existing retry, circuit-breaker, quota, or combo failover behavior

# Technical Design

### Validation Approach
Run `cargo test -p rook-usecases` after each stage. Focus on pure normalization tests first, then integration.

### Key Scenarios

**Normalization:**
- `[10, 20, 30]` → `[1.0, 0.5, 0.0]` (inverse min-max)
- Equal known values `[20, 20, 20]` → `[0.5, 0.5, 0.5]`
- Single known value → `0.5`
- No known values → `Unknown`
- Mixed known/unknown: unknowns don't affect bounds, stay unknown
- Known zero vs unknown: `Known(0)` enters bounds, unknown doesn't
- p50 and p95 normalized separately
- Incompatible cost dimensions never pooled
- Invalid/negative/non-finite → `Unknown(reason)`

**WeightedRandom:**
- Valid weights: existing behavior preserved
- Length mismatch vs full registry → explicit error
- Negative weight → explicit error
- NaN/Inf weight → explicit error
- All-zero weights → explicit error
- Post-filter subsets retain correct provider-weight association

**Legacy behavior:**
- Priority returns same target as pre-change for fixed fixtures
- RoundRobin rotation unchanged
- No eligible candidates → existing `all_providers_exhausted` error
- Circuit-breaker, quota, retry behavior unchanged

**Integration:**
- Completion path: snapshot built, reason produced
- Streaming path: snapshot built, reason produced
- Reevaluation discards stale snapshot
- Combo paths: preserved Priority behavior, no scoring injection

### Edge Cases
- Provider-scoped telemetry mapped correctly (never relabeled as connection-specific)
- Missing pricing mapping → `Unknown(Missing)`, not free cost
- Telemetry disabled → `Unknown(SourceUnavailable)`
- Same eligible set, permuted order → identical normalization results
- Weighted reproducibility tests use fixed RNG seed

# Delivery Steps

### ✓ Step 1: Implement scoring types and pure normalization
Create `scoring.rs` with all scoring types and pure normalization functions.
- Add `UnknownReason` enum: `Missing`, `Invalid`, `NonFinite`, `IncompatibleBasis`, `SourceUnavailable`
- Add `ScoreComponent` with `raw: Known(T) | Unknown(UnknownReason)` and `normalized: Option<f64>`
- Add `CandidateSignals` with p50/p95 latency, pricing dimensions, priority, quota state, circuit state
- Add `SignalsSnapshot` with timestamp and `HashMap<TargetRef, CandidateSignals>`
- Add `SelectionReason` with selected target, method, components, fallback code
- Implement `normalize_component()` — inverse min-max: `(max - value) / (max - min)`, equal/single → 0.5, no known → unknown
- Implement `build_snapshot()` — acquire telemetry (provider-scoped p50/p95), pricing (per-dimension), circuit, quota
- Export from `lib.rs`
- Add pure normalization unit tests covering all acceptance criteria: [10,20,30]→[1,0.5,0], equal→0.5, single→0.5, empty→unknown, mixed known/unknown, zero vs unknown, invalid/negative/non-finite, p50/p95 separate, incompatible cost dimensions

### ✓ Step 2: Harden WeightedRandom with explicit errors
Replace silent first-candidate fallback with typed errors in `router_impl.rs`.
- Add `validate_weights()` — checks length vs full registry, non-negative, finite, non-all-zero
- Change `select_weighted()` to return `Result<Option<Arc<dyn ProviderPort>>, CortexError>`
- Replace `candidates.first()` fallback with `Err(CortexError::weighted_config_error(...))`
- Propagate error through `select()` and `select_excluding()`
- Add `CortexError` variant for weighted configuration errors (e.g., `weighted_config_error`)
- Preserve valid weighted selection behavior identically
- Add tests: length mismatch error, negative weight error, NaN/Inf error, all-zero error, valid post-filter subset retains weights, fixed-RNG reproducibility

### ✓ Step 3: Integrate scoring into completion and streaming paths
Wire scoring between eligibility and selection in `route_request.rs`.
- In `prepare_attempt()`: after `eligibility_result()` succeeds, build `SignalsSnapshot` from eligible candidates using `self.telemetry` and `self.pricing`
- After `router.select_excluding()` returns, build `SelectionReason` from snapshot and selected provider
- Store `SelectionReason` in `EligibleAttempt`
- On `Reevaluate`, discard the scoring snapshot (it's rebuilt on retry)
- In `select_stream_provider()`: same pattern — build snapshot from eligible, build reason after selection, store in `StreamSelection`
- On registry mismatch (snapshot recheck), discard scoring results
- Add integration tests: completion path produces reason, streaming path produces reason, reevaluation discards snapshot, combo paths unchanged, legacy Priority regression

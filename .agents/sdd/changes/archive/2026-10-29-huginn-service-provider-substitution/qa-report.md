## 3. Target, environment, permissions and limits

- **Target:** productive local Huginn composition. It includes the publication of `LeasedAgentLoop` by the application/runtime builders and the dynamic readiness read in `apps/huginn`.
- **Environment:** local macOS worktree, Cargo, workspace Rust tests and temporary bases/resources isolated by the tests. The tests use controlled providers and stores; the locks/persistence test exercises a temporary local SQLite database.
- **Permissions and data:** no external credentials, production services or persistent user data were used. No data reset was performed. There was no commit, push or publication.
- **TUI observability:** the existing PTY/subprocess tests were executed. Those tests have no observable control to substitute a provider inside the same running TUI. The spec does not define that interaction as separate acceptance; no command or UI action was invented.
- **Builder scope:** the runtime tests observe `build_native`, `build_native_with_connections` and `build_native_with_connections_and_guards` separately. The CLI test uses the builder with connections/guards for the normal flow and is not counted as rebind proof. Substitution coverage for that builder comes from the new in-process test.

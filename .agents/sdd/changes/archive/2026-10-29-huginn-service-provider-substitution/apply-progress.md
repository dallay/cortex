## RED → GREEN → REFACTOR evidence for batch 3.1–3.9

1. **RED, slots:** tests were added for the current provider, the previous lease, the `acquire()`/commit race, and the timeout. Before implementation, `cargo test -p huginn-core --test service_lease service_slot` failed with `E0599`: `Supervisor::service_slot_handle` did not exist.
2. **RED, precommit cleanup:** `cargo test -p huginn-core --lib staged_abort_tests` failed in the two expected scenarios. The staged resource counter remained at `0` when a gate was missing after staging and when the closure failed because of a poisoned mutex; the tests required `1`.
3. **GREEN:** `ServiceSlotHandle<T>` was implemented on top of the synchronized global table. The acquisition reads value and gate, validates the type, and increments the counter before releasing the mutex. `ServiceHandle<T>` keeps its generation-bound semantics and `resolve() -> Arc<T>` did not change.
4. **GREEN for commit and rollback:** the commit replaces all staged slots under a single critical section. Dynamic admission and the lease increment share the table synchronization. Aborts reopen gates, discard the staged plugin, record the result, and resume the attempted dependents. The cleanup covers missing gates and closure failures after staging.
5. **REFACTOR:** precommit abort was centralized, the mutex was kept outside any `await`, and `LeaseGuard::drop` releases the counter before notifying. The kernel does not incorporate knowledge of `ModelService` nor `SessionStore`.

The first run of the slot test had an invalid expectation: it tried to complete the commit while holding the previous lease, although the substitution must wait for that lease to finish. The test was adjusted to check that the lease stays active during the wait, to release it, and then to check the new provider.

## TDD follow-up for 3.8–3.9: publication and overflow

1. **RED, commit callback:** `cargo test -p huginn-core --lib failed_slot_publication_does_not_run_commit_callbacks` reproduced the failure. With `service_slots` poisoned, the callback ran before the failure was detected (counter `1`, expected `0`); the test also requires cleanup of the staged resource.
2. **RED, counter:** `cargo test -p huginn-core --lib lease_counter_overflow_returns_an_error_without_poisoning_the_gate` reproduced an overflow panic in `active += 1`.
3. **GREEN:** `publish_staged_plugin` performs a table preflight acquisition before running the callbacks. It releases the mutex before invoking them to avoid deadlocks from reentrancy and does not extend the critical section. Afterwards it acquires the mutex again to publish.
4. **Synchronization rationale:** between the preflight and the publication, an ordinary acquisition does not run plugin code under the table mutex; the only counter operation uses `checked_add`. Therefore the normal concurrency of `acquire()` cannot poison that mutex in that interval. If the table is already poisoned, the preflight fails before the callbacks and leaves the staged context available for cleanup. It is not asserted that any exceptional panic is recoverable.
5. **REFACTOR:** the overflow returns `AgentError` without modifying the counter or poisoning the gate or the global slots mutex. The test uses the real `ServiceSlotHandle::acquire` path and verifies that both mutexes stay healthy. The focused tests were run and then the full package suite.

## Limits and risks

- The concurrent test exercises acquisitions of a slot while the commit happens and checks that each lease obtains a valid value; it also checks all affected handles after the commit. The API does not offer a multi-slot snapshot/acquisition, so it is not asserted that global atomicity across several slots was observed concurrently. The atomicity is implemented by holding the global mutex during all the commit updates.
- The lease contract remains cooperative. `resolve() -> Arc<T>` and cloned references that survive outside a lease do not obtain strong revocation.
- The timeout does not cancel an active lease. It keeps the previous provider, reopens its admission, and allows a retry after the lease is released.
- The productive application and runtime builders register the private adapter `LeasedAgentLoop`; direct use of `LoopPlugin(pub LoopConfig)` remains legacy/static and does not obtain rebind.
- The additive public factory `huginn_application::composition::leased_loop_plugin` was added so that the runtime crate can register the private concrete type without exposing `LeasedLoopPlugin`.
- `StandardLoop` keeps its six public fields, their signatures, and the current struct literals. The rebind guarantee of the productive loop applies to `LeasedAgentLoop` and only covers the operations that hold the leases.
- The readiness queries the current generation of the slot on every call; separate CLI/TUI processes do not demonstrate a substitution within the same process.
- Sessions are not migrated when `SessionsService` changes; `SqliteSessions::lease/load/list` stay outside that service.
- Verify and QA allow archiving with warnings; operator acceptance is not asserted.
- Before preparing a PR, resolving the layer/base metadata for the `feature-branch-chain` strategy is still pending; no topology was inferred here.

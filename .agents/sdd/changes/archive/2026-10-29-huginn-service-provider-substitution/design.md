# Design: Dynamic Rebind with a Compatible `StandardLoop` API

> **Change**: `huginn-service-provider-substitution` · **Issue**: #509 · **Phase**: design reopened

## Evidence and decision

`loop_engine` is public (`crates/huginn/application/src/lib.rs`); `StandardLoop` and its six fields are public (`crates/huginn/application/src/loop_engine.rs`). There are struct literals in `crates/huginn/application/tests/providers_turns.rs` and `crates/huginn/runtime/tests/coding_workflow.rs`, `crates/huginn/runtime/tests/providers_integration.rs`, and `crates/huginn/runtime/tests/stream_persistence.rs`. Changing types/fields would break those consumers. The compatible solution keeps `StandardLoop`, its fields, and its signatures exactly; it does not turn `model`/`sessions` into slots.

| Option                                                     | Cost                                                | Decision                                                                                   |
|------------------------------------------------------------|-----------------------------------------------------|---------------------------------------------------------------------------------------------|
| Change the public fields of `StandardLoop` to handles      | Breaks struct literals and the type contract.       | Rejected.                                                                                   |
| Keep `StandardLoop`; dynamic wrapper + shared core        | Adds a private adapter and factors out execution.   | Chosen; it preserves the API and avoids duplicating behavior.                              |
| Locks per slot                                             | More concurrency, but requires a group protocol.     | Rejected in favor of the global mutex, which synchronizes value/gate read and increment.   |

In `crates/huginn/core/src/kernel.rs`, `PluginContext::resolve` uses captured services; `Supervisor::start` activates ready plugins in one pass and `LoopPlugin::activate` only receives a context (`crates/huginn/application/src/composition.rs`). Therefore `Supervisor::service_slot_handle` is not accessible in `activate`. Option A is kept: `PluginContext::service_slot_handle<T>(&ServiceId)` creates a handle only for IDs in `Manifest.requires` and rejects an undeclared requirement, an absent slot, or an incompatible type. `activate_plugin` and `stage_plugin` pass the manifest's `required_services` and `service_slots: self.service_slots.clone()`; there are no capability branches.

The table stores `ServiceId` → `ServiceSlot { value, gate }`; `ServiceSlotHandle<T>` retains the table and the ID. `acquire()` reads value and gate and increments the lease under the shared synchronization. After stage and drain, a commit replaces all slots and revokes the previous gates jointly; it does not publish partial generations. `resolve() -> Arc<T>`, `ServiceHandle<T>`, and `huginn-plugin-api::v1` remain unchanged.

## Shared execution and lifecycle

Factor the execution into `LoopExecution<'a>`: per-operation references to model/sessions and stable references to tools, instructions, config, and lifecycle. Share there `pin_model`, `record`, `request`, `context`, `summarize`, `collect_response`, `execute_tool`, `turn`, `run`, `compact`, `run_with_skills`, and `run_with_skills_and_catalog`; `skill_commands` keeps the common logic without leases. `StandardLoop` keeps its public fields and signatures, delegates with static services, and leaves the struct literals of the tests intact.

Production uses `LeasedAgentLoop`, an `AgentLoop` adapter that does not contain `StandardLoop` nor retain old `Arc`s of model/sessions. The public builders `huginn_runtime::composition::{build_native, build_native_with_connections, build_native_with_connections_and_guards}` call the private helper `build_native_plugin`, which registers the leased loop through the public factory `huginn_application::composition::leased_loop_plugin`. The public builder `huginn_runtime::composition::build` delegates to `huginn_application::composition::build`, which uses that same factory. The factory is the shared seam: both productive paths guarantee dynamic rebind and leases. The adapter acquires admission and both slots before effects; it creates `LoopExecution` with its services and keeps the leases during the whole `run`/`compact`, including streams, tools, approvals, and saves. If the second lease fails, RAII releases the first without mutating the session.

`LoopAdmission` rejects new operations and waits for the active ones; during the closure, a run fails before effects. The timeout does not cancel active runs; abort reopens admission and keeps the previous provider. The public APIs of `StandardLoop` and `LoopPlugin(pub LoopConfig)` are preserved. Legacy exception: direct use of `StandardLoop` or `LoopPlugin` keeps the static loop, without dynamic rebind. The `LeasedLoopPlugin` type is private and implements `Plugin::supports_drain`, `Plugin::drain`, and `Plugin::resume`; those hooks coordinate `Arc<LoopAdmission>` with `LeasedAgentLoop`. There is no need to expose the adapter or change the legacy APIs, and no human decision is pending on a public type name.

## Readiness, persistence, and files

`apps/huginn/src/main.rs` queries `ServiceSlotHandle<ModelService>` for doctor, CLI, and TUI readiness; it does not retain `Arc<ModelProvider>` nor a stale `bool`. `SqliteSessions::lease`, `load`, and `list` (`crates/huginn/runtime/src/sessions.rs`) remain direct to the runtime, outside `SessionsService` and outside rebind; there is no lease transfer and no state/schema migration.

| Path                                                                | Planned change                                                                                                                                                                                                                                          |

| `crates/huginn/core/src/kernel.rs`                                  | Slots, context, and synchronized publication.                                                                                                                                                                                                              |

| `crates/huginn/core/tests/service_lease.rs`                         | RED: a handle retained by a dependent sees the new provider after `substitute`; test `Manifest.requires`/type/presence validation.                                                                                                                            |

No new dependencies. Run the focused tests and `just huginn-architecture`; this is not equivalent to full CI.

## Risks

The private adapter avoids breaking `StandardLoop` and `LoopPlugin`, at the cost of an extra composition layer. The lease guarantee is cooperative and does not cover `Arc` values retained outside a lease nor detached work.

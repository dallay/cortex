## Bloqueos

Diagnóstico de `SIGABRT` (2026-11-09): la ejecución directa de `/usr/bin/sandbox-exec` con el perfil restrictivo actual termina también en código 134 para `/usr/bin/true` y `/bin/sh -c 'exit 0'`; por tanto, el wrapper Rust/`process-wrap` no es causa necesaria. El perfil es aceptado por el parser (un perfil sintácticamente inválido devuelve 65), pero sus reglas actuales no permiten iniciar esos procesos. Un perfil diagnóstico con `(allow file-read*)` funciona. Un perfil con `(import "system.sb")`, `deny default`, reglas explícitas de proceso/rutas y `(deny network*)` también inicia el shell y permite lectura/escritura en un workspace canónico; devuelve `Operation not permitted` al intentar leer un marcador externo. Esto acota el fallo a las reglas/baseline del perfil, pero NO identifica la operación exacta que provoca el aborto. `system.sb` se declara interfaz privada de Apple, contiene permisos de sistema adicionales y no debe adoptarse sin auditar sus efectos; la prueba manual tampoco
demuestra todavía denegación de red ni aprobación para producción. El shell emitió además errores de lectura denegada para `/private/var/select/sh`, aunque terminó con código cero.

La prueba externa ahora exige `shell-started` y una salida normal del shell distinta de cero antes de aceptar que el marcador no se leyó. RED corregido: ambas pruebas macOS fallan con `SIGABRT`; el marcador de inicio no aparece. Esto confirma que el resultado anterior no era una denegación atribuible al comando y mantiene la fase bloqueada.

RED previo de la aserción reforzada (reportado por el usuario): sin sandbox, el comando leyó el marcador externo y terminó con estado 0. La prueba ahora invoca explícitamente `/bin/cat` con `LC_ALL=C` y exige su diagnóstico `Operation not permitted` para la ruta existente, además del sentinel, estado normal no-cero y ausencia del secreto. En la ejecución macOS actual, `cat` produjo ese diagnóstico para el marcador; una primera ejecución falló solo porque el nombre de diagnóstico del sistema fue `cat`, no `/bin/cat`. Tras ajustar la aserción al nombre emitido, el test enfocado pasó. Esta verificación no cambia policy/launcher ni completa enforcement.

Las pruebas unitarias de SBPL no sustituyen enforcement real. No contar `SIGABRT` como denegación. Antes de ampliar el perfil, identificar el permiso mínimo faltante y comprobar los efectos de cualquier importación de sistema. Fallo o ausencia de runner requerido mantiene el resultado **BLOCKED**. Apple depreca Seatbelt; no prometer soporte futuro. Grants solo podrán tratarse en otro cambio tras pruebas independientes de aislamiento/estado en todos los sistemas aplicables; no implementarlos aquí.
